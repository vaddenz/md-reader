# md-reader v1.1 · 增量设计方案（Design Spec）

> 日期：2026-10-18 · 状态：待用户评审
> 关系：本文件是 `docs/specs/2026-10-18-md-reader-design.md`（v1.0 权威设计）的**增量设计**，只定义 v1.1 新增的四个特性；v1.0 的其余设计继续有效。若两文件冲突，在本文件覆盖的范围内以本文件为准。

## 1. 概述

### 1.1 本次范围（四个特性）

1. **阅读排版设置**：字体选择（系统默认 / 等线风 / 宋体风）、正文字号、表格与引用的字号比例。
2. **显示方向**：手动横屏（含 180° 翻转）与默认竖屏锁定；全手动，不跟随传感器。
3. **文字高亮**：选中文字 → 黄/红底色，持久保存（本机元数据 + 导出/导入备份）。
4. **自定义右键菜单**：阅读正文内替代浏览器菜单（复制 / 高亮 / 清除高亮 / 全选）。

### 1.2 已确认的决策（讨论结论）

- 高亮存**本机 IndexedDB**（kv），不写回仓库；记录模型**可扩展**（decorations 数组，未来加颜色/下划线/波浪线零迁移）。
- 字体用上游**完整字体包**（不做子集化），交付为**无损**转换的 WOFF2。
- 方向控制**全手动**：默认锁定竖屏；主路径为 PWA（主屏幕应用）内的系统级方向锁定；不做 CSS 旋转模拟；浏览器标签下锁被拒时自动进入全屏后重试（验收修复）。
- 版本号 **v1.1.0**。

## 2. 全局约束

- 技术栈与工程结构不变（React 18 + TS + Vite + IndexedDB + hash 路由）；**不新增运行时依赖**。
- 新增 devDependency：Node 端 WOFF2 转换工具（仅字体脚本使用）。
- 既有测试（146 单测 + 25 e2e）必须全绿；新功能按同口径补测。
- CSP 不变（`font-src 'self' data:` 已允许自托管字体）；不新增外部网络源。
- 改动只作用于**阅读页、设置页**与新增的样张页；应用其他区域行为不变。

## 3. 阅读排版设置

### 3.1 配置模型

新模块 `src/data/appearance.ts`（与 `src/data/prefs.ts` 同模式：kv 读取 + 清洗 + 写入串行化）。

```ts
type FontChoice = 'system' | 'xihei' | 'serif';
interface ReaderAppearance {
  fontFamily: FontChoice;   // 默认 'system'
  fontSize: number;         // 12–24（px），默认 17
  tableScale: number;       // 0.5–1.2，默认 0.95
  quoteScale: number;       // 0.5–1.2，默认 1.0
}
```

- kv 键：`appearance`；读取失败或字段非法时回退默认值并钳制范围（`sanitizeAppearance`）。
- 默认值口径 = v1.0 现状（17px / 表格 0.95em / 引用 1em），未设置过的用户视觉零变化。

### 3.2 应用方式（CSS 变量）

纯函数 `appearanceStyle(a): CSSProperties` 生成变量，以内联 style 挂在阅读容器上（`.doc-content` 与设置预览容器共用）。

| 变量 | 值 | 作用 |
| --- | --- | --- |
| `--r-font-family` | 见下方字体栈表 | 正文/标题字体 |
| `--r-font-size` | `17px` 等 | 正文字号 |
| `--r-table-scale` | `0.95` 等 | 表格字号比例 |
| `--r-quote-scale` | `1` 等 | 引用字号比例 |

字体栈（`FontChoice` → `font-family`）：

| choice | 栈 |
| --- | --- |
| `system` | `var(--font-sans)`（现状栈） |
| `xihei` | `'LXGW Neo XiHei Screen', var(--font-sans)` |
| `serif` | `'Noto Serif SC', serif` |

`src/styles/content.css` 修改点：

- `.doc-content`：`font-size: var(--r-font-size, 17px)`；新增 `font-family: var(--r-font-family, var(--font-sans))`。
- `table`：`font-size: 0.95em` → `calc(1em * var(--r-table-scale, 0.95))`。
- `blockquote`：新增 `font-size: calc(1em * var(--r-quote-scale, 1))`。
- `pre code`：`13px` → `calc(var(--r-font-size, 17px) * 0.765)`（默认口径与现状 13px 一致，随正文字号缩放）。
- 标题为 em 基准，随正文字号自动缩放；代码字体保持 `--font-mono`，不受字体选择影响。

### 3.3 设置页 UI（新增「阅读外观」区）

| 控件 | 类型 | 范围 / 默认 |
| --- | --- | --- |
| 字体 | 三选一（单选） | 系统默认 / 等线（霞鹜新晰黑·屏幕版）/ 宋体（思源宋体） |
| 正文字号 | 滑块（step 1） | 12–24px，默认 17px |
| 表格字号比例 | 滑块（step 5） | 50%–120%，默认 95% |
| 引用字号比例 | 滑块（step 5） | 50%–120%，默认 100% |

- **实时预览块**：正文段（含行内代码/链接）+ 引用 + 小表格样张，套用同一套变量，改动即时生效。
- 持久化：改动即时预览、**防抖（约 300ms）**写入 kv；无「保存」按钮。
- 附「并排样张」入口 → `#/font-preview`（字体定稿确认用）。

### 3.4 字体样张页（`#/font-preview`）

- 内部路由，不在主导航中；设置页链接进入。
- 内容：同一段样张分别以 系统默认 / 等线 / 宋体 渲染，纵向排列（手机上「并排」即上下对比），含标题、正文、引用、表格、代码。
- 用途：真机验收时确认字体定稿；字体为可替换部件，后续更换零结构改动。

### 3.5 读取与生效时机

- DocPage 打开文档时与正文读取**并行**加载外观配置，避免可见闪烁；设置页与样张页同样在挂载时读取。
- 仅作用于阅读正文与设置/样张预览；搜索页、首页等应用 UI 不受影响。

## 4. 字体交付

### 4.1 字体清单

| 档位 | 字体 | 字重 | 上游 | 许可 |
| --- | --- | --- | --- | --- |
| 等线风 | 霞鹜新晰黑·屏幕阅读版（LXGW Neo XiHei Screen，取补全 Full 变体） | 单字重（标题用浏览器合成加粗） | GitHub `lxgw/LxgwNeoXiZhi-Screen` Releases | IPA Font License 1.0 |
| 宋体风 | 思源宋体 / Noto Serif SC | Regular + Bold | notofonts / Google Fonts 静态包 | SIL OFL 1.1 |

- 具体上游文件与版本号在实现时**锁定并记录**在脚本注释与 README 中。
- 完整字符集，不做子集化；预计仓库体积增加约 15–25MB（已确认接受）。

### 4.2 获取与转换（一次性脚本）

- `scripts/fonts.mjs`（dev 脚本，`npm run fonts`）：
  1. 从上游固定 URL 下载字体包到临时目录；
  2. **无损**转换为 WOFF2（仅格式转换，字形全集不变）；
  3. 产物写入 `public/fonts/`，同时拷贝各字体许可文本到 `public/fonts/licenses/`。
- 转换产物**入库**（避免构建时联网）；脚本幂等，可重跑。
- 不在 CI/构建中执行字体下载。

### 4.3 加载与缓存

- `src/styles/fonts.css`：`@font-face` 声明（家族名用上游原名），`font-display: swap`；URL 带部署 base 前缀。
- **按需加载**：浏览器只在字体被实际使用（选中该档）时请求；未选过的字体不占流量。
- PWA 缓存（`vite.config.ts` workbox 调整）：
  - `globIgnores: ['**/fonts/**']` —— 字体**不**进预缓存清单（避免装 PWA 时强制下载全部字体）；
  - 新增 runtimeCaching：`/fonts/` 下 woff2 → `CacheFirst`，缓存名 `mdreader-fonts`，长期过期（约 1 年，maxEntries 少量）。
- 离线语义：某字体首次使用后离线可用；从未使用过的字体离线时回退系统字体（`swap`，不影响阅读）。

### 4.4 许可与致谢

- 许可文本随仓库分发（`public/fonts/licenses/`）；README 与「关于」页增加字体来源与致谢。
- 不重命名字体、不修改字形（仅格式转换），符合两份许可的分发条件。

## 5. 高亮

### 5.1 数据模型

新模块 `src/data/highlights.ts`（kv 读取 + 清洗 + 写入串行化）。

```ts
interface Decoration { kind: 'bg'; color: HighlightColor }   // v1 仅 bg；未来追加 kind 即可
interface HighlightRecord {
  id: string;                 // crypto.randomUUID()
  exact: string;              // 选中原文（渲染可见文本）
  prefix: string;             // 前文最多 32 字符
  suffix: string;             // 后文最多 32 字符
  decorations: Decoration[];  // 可组合、可扩展
  createdAt: number;
}
// kv 键 'highlights' → { [docPath: string]: HighlightRecord[] }
```

- **颜色注册表**（渲染与菜单共用）：`{ id, label, cssVar }`，v1 为 `yellow`（明黄，初值 `#ffeb3b`）、`red`（初值 `#ff8a80`）；色值经 CSS 变量定义在 content.css，真机微调不动数据。
- 记录以**文档路径**为键（与收藏/进度同策略）：同步更新 sha、内容过期、甚至文档删除都不影响记录。
- 清洗：字段缺失/类型错误 → 丢弃该记录；未知 `kind`/颜色的 decoration → **保留数据、渲染时忽略**（向前兼容导出/导入）。

### 5.2 锚定算法（新模块 `src/markdown/highlights.ts`）

**可见文本索引（haystack）构建**：遍历 `.doc-content` 文本节点，**跳过**：`script/style/pre/code/button/.code-copy/.mermaid/svg/.md-img-error`；同块内节点直接相连，跨块级边界插入 `\n` 分隔（避免跨块假匹配）。

**匹配（按记录 `createdAt` 顺序逐条执行）**：

1. **精确匹配**：在原始 haystack 中找 `exact` 的全部出现位置；
2. **空白归一化匹配**（上一步无命中时）：双方折叠空白串后匹配（处理换行/缩进/空格差异）；
3. **消歧**：候选多于一个时，用 `prefix`/`suffix` 与候选处上下文比对（公共前后缀长度计分），取最高分；平分取最早位置；
4. **孤儿**：无候选 → **保留记录、本次不渲染**；原文恢复后自动重现。

**应用**：匹配区间映射回原始文本节点（支持跨节点、跨段落选区），逐段包裹 `<mark class="hl hl-<color>" data-hl-id="…">`；若与本次已应用的记录区间相交（内容编辑后可能发生），按创建时间**先到先得**，后者本次不渲染（记录保留）。

### 5.3 渲染与集成

- DocPage 新增 DOM pass：`useEffect [html, path]`，位于「图片/mermaid 惰性加载」之后、「搜索高亮 + 滚动恢复」之前；
- 每次打开 / 同步更新正文后自动重锚；导入高亮后对当前文档重跑一次；
- 与搜索高亮共存：搜索 pass 同步先执行（跳过既有 `<mark>`，但此时持久高亮尚未应用），高亮 pass 异步后到（读 IDB），持久 `mark.hl` 可能被包进 `mark.search-mark` 内；颜色仍以高亮样式为准（`.doc-content mark.hl-*` 规则在同优先级下后置）；
- 高亮为行内元素，不影响布局高度与滚动恢复。

### 5.4 交互策略

- **创建**：由右键菜单触发（见 §6）；选区映射为 haystack 区间（无需搜索）→ 生成 `exact/prefix/suffix` → 先**移除与该区间相交的已渲染高亮记录**（避免嵌套），再落新色 → 持久化 → 清除选区。
- **重叠策略**：同一区间重新高亮另一种颜色 = 替换（先清相交旧记录）；不产生嵌套记录。
- **清除高亮**：菜单项，按选区相交（或点中 `data-hl-id`）移除记录并即时取消渲染。
- **代码块不参与**：选区落在排除区（代码等）时菜单不提供高亮（见 §6.2）。
- **开关式重复点击**：对已有同色高亮重复「高亮·黄」为幂等（先清后加，结果不变）。

### 5.5 导出与导入

- 设置页「高亮数据」区：**导出 JSON** / **导入**。
- 导出格式：`{ formatVersion: 1, exportedAt, highlights: {…} }`，文件名 `md-reader-highlights-<yyyymmdd>.json`；孤儿记录一并导出。
- 导入：文件选择 → 解析 → 清洗 → **合并去重**（键 = `path + exact + decorations`，重复跳过、不覆盖本地已有）→ toast 反馈「导入 N 条（跳过重复 M 条）」；解析失败给错误提示。

### 5.6 边界与已知限制

- 高亮文字本身被改写且无法模糊命中 → 孤儿（保留、不显示、可导出）。
- 文档从仓库删除 → 记录保留（与收藏一致）。
- 数据仅本机：清站点数据会丢失（靠导出备份）；记录键为文档路径，不含仓库标识（沿用收藏/进度现状，单仓库自用场景）。

## 6. 自定义右键菜单

### 6.1 触发与抑制

- 在 `.doc-content` 上监听 `contextmenu`（桌面右键 / 安卓长按），**始终 `preventDefault`**（阅读正文内不再出现浏览器菜单）。
- 应用其他区域（设置输入框、搜索框等）**保持原生菜单**，不影响粘贴等操作。

### 6.2 菜单项与判定（纯函数 + 注册表）

| 情境 | 菜单项 |
| --- | --- |
| 有选区（普通文本） | 复制 ｜ 高亮·黄 ｜ 高亮·红 ｜（选区与已渲染高亮相交时）清除高亮 |
| 有选区（与排除区相交，如代码块） | 复制 |
| 无选区（点在高亮上） | 清除高亮 ｜ 全选 |
| 无选区（普通） | 全选 |

- 「复制」= `navigator.clipboard.writeText(selection.toString())`，成功/失败给轻提示（沿用现有文案模式）。
- 「全选」= 选中 `.doc-content` 全部内容（Range）。
- 高亮动作来自颜色注册表（数据驱动），未来加颜色/下划线只加注册表项与样式。

### 6.3 组件行为（新组件 `src/components/SelectionMenu.tsx`）

- 出现于触点位置（clientX/clientY），超出视口自动收边；轻量浮层，样式与现有 UI 一致。
- 关闭：点外部、滚动、Escape、路由变化、再次触发。
- 语义：`role="menu"`/`menuitem`；基础键盘支持（Escape 关闭）。

### 6.4 真机验证点与备选

- 安卓长按可能同时出现原生「选择工具栏」（Chrome 行为差异）；验收时确认原生菜单已被压制。若工具栏仍残留且干扰体验，备选交互：**长按后于选区附近显示浮动操作按钮**（同一套动作，交互形态替换）。
- 桌面右键同路径生效（附带收益）。

## 7. 显示方向

### 7.1 状态模型

- 三态：`'portrait'`（默认）｜ `'landscape'` ｜ `'landscape-flipped'`。
- 持久化：kv 键 `orientation`；启动时读取并应用。
- 语义：**全手动**——竖屏锁定为默认态；任何状态都不跟随传感器。

### 7.2 机制

- 映射与锁定（新模块 `src/lib/orientation.ts` + `src/state/OrientationContext.tsx`，与 TokenContext 同模式）：

| 状态 | 锁定调用 |
| --- | --- |
| `portrait` | `screen.orientation.lock('portrait')` |
| `landscape` | `screen.orientation.lock('landscape-primary')` |
| `landscape-flipped` | `screen.orientation.lock('landscape-secondary')` |

- 应用时机：应用启动（读取 kv 后）、状态变更时。
- 失败处理（验收修复：全屏降级）：`lock()` 被拒/不支持时先按原口径重试一次——若当前不在全屏，则在用户手势上下文内自动 `requestFullscreen()` 后重试 `lock()`；重试成功视为锁定成功。
  - 回竖屏：若此前为横屏锁定进入过全屏，先 `exitFullscreen()` 再尽力 `lock('portrait')`（不为竖屏请求全屏）；竖屏失败静默（退出全屏已生效，不打扰）。
  - 仍失败（全屏请求被拒/不可用）时——**启动时静默**；**用户操作触发横屏/翻转时** toast 提示「当前环境不支持方向锁定：请用主屏幕应用（PWA）打开」。
- manifest **不设** `orientation` 字段（静态方向会与运行时切换冲突；运行时控制是唯一权威）。

### 7.3 UI 入口

- 设置页「显示方向」区：三态单选 + 说明文案（建议主屏幕应用打开）。
- 阅读页头部（DocHeader）新增：
  - 「横屏/竖屏」开关按钮：竖屏态 → 切到横屏（**记忆上次横屏方向**，未用过则默认方向）；横屏态 → 切回竖屏锁定；
  - 「旋转」按钮：仅横屏态显示，点击在 `landscape ⇄ landscape-flipped` 间翻转；
  - 两按钮状态与设置页、kv 完全同步。

### 7.4 降级与边界

- 浏览器标签（未全屏）：锁定请求会被拒 → 自动进入全屏后重试，成功即正常使用（验收修复：**已实现**全屏降级路径）；仅当全屏请求本身也被拒（无手势/策略禁止）时才按 §7.2 提示安装到主屏幕。
- 桌面端：不支持方向锁定 → 同样提示，不影响阅读。
- 由系统/用户退出全屏等场景：状态保持，重新尝试应用；失败静默（非用户操作触发时不打扰）。

## 8. 测试与验收

### 8.1 单元测试（新增）

- `appearance`：清洗/钳制/默认值；`appearanceStyle` 映射。
- `highlights`：锚定全场景（精确、多候选消歧、空白归一化、孤儿、恢复、跨节点/跨段、冲突先到先得）；清洗；导出/导入合并去重。
- 菜单判定纯函数：四种情境 → 项集。
- `orientation`：状态映射；`lock` 成功/失败（stub）；持久化。

### 8.2 e2e（新增）

- **菜单**：派发 `contextmenu` → 菜单出现与项集；复制（stub clipboard）；创建高亮 → `mark.hl-yellow` 出现；代码块选区仅「复制」。
- **高亮**：创建 → 刷新仍在；mock 文本更新（增删前后内容）→ 重锚跟随；改写高亮文字 → 孤儿（DOM 无 mark、IDB 记录仍在）；清除高亮；导入后当前文档即时渲染。
- **排版**：改字号/比例 → 断言 `.doc-content` 计算样式；切字体 → CSS 变量生效；刷新持久；预览块联动。
- **方向**：`addInitScript` stub `screen.orientation.lock`（记录调用）→ 启动锁竖屏、头部切换/翻转的调用序列、刷新后状态保持、失败时用户操作给出提示。
- **PWA**：生成的 SW 预缓存清单**不含**字体（`globIgnores` 生效）；字体 URL 可访问。
- 既有 146 单测 + 25 e2e 全量回归。

### 8.3 真机验收清单（用户执行）

1. 设置页切字体/字号/比例 → 阅读页即时生效、重启保留；样张页并排对比确认字体定稿。
2. 长按选中文字 → 自定义菜单出现（浏览器菜单不出现）；复制可用；黄/红高亮生效、观感确认。
3. 高亮：刷新/重启保留；在仓库改动笔记（高亮前后增删内容）→ 同步后高亮跟随；导出 JSON → 清除站点数据 → 导入恢复。
4. 方向：头部「横屏」→「旋转」→ 退出；重启后方向状态保持；浏览器标签打开时自动进入全屏并锁定横屏（锁被拒时全屏降级后重试，§7.4），点回「竖屏」退出全屏——仅当全屏请求本身也被拒时才提示安装到主屏幕。
5. 原功能抽查：阅读、搜索、收藏、进度、离线横幅。
